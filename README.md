# Arix Platform

Платформа управления моделями: реестр моделей провайдеров, playground с реальным
стримингом, треды, раны и трейсы. Поверх неё работает Telegram-агент продаж.

Всё, что показано в интерфейсе, записано реальными запросами. Строка в `runs`
появляется только после того, как запрос действительно ушёл к провайдеру.

## Быстрый запуск (Windows, без Docker)

```bat
start-local.bat
```

Вручную:

```powershell
# Backend
cd backend
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# Frontend (другой терминал)
cd frontend
npm install
npm run dev
```

- **Платформа:** http://localhost:3000
- **API / Swagger:** http://127.0.0.1:8000/docs

## Разделы интерфейса

| Раздел | Что показывает |
|--------|----------------|
| **Overview** | Раны за 24ч, токены, p50/p95 латентности, расходы, карта нитей |
| **Playground** | Реальный SSE-стрим к выбранной модели; создаёт тред, ран и спаны |
| **Threads** | Все нити — из Playground, API и Telegram |
| **Models** | Каталог, загруженный из API провайдеров; тест задержки, default |
| **Traces** | Список ранов, водопад спанов, prompt/output, ошибки |
| **Knowledge** | Документы для retrieval-augmented ранов |
| **Settings** | Статус ключей, дефолтная модель, промпты агентов |

Дизайн строго монохромный: в теме Tailwind не объявлено ни одного цветного
токена, поэтому цвет не может попасть в интерфейс случайно. Есть светлая и
тёмная темы.

## Провайдеры

```env
OPENAI_API_KEY=...      # каталог тянется через client.models.list()
ANTHROPIC_API_KEY=...
GOOGLE_API_KEY=...
```

После добавления ключа: **Models → Sync providers**. Список моделей не
захардкожен — он приходит из API провайдера.

### Работа без ключей

В комплекте есть OpenAI-совместимый локальный сервер, чтобы прогнать платформу
end-to-end до покупки ключей:

```powershell
python backend/tools/local_provider.py     # 127.0.0.1:8800
```

```env
OPENAI_API_KEY=local
OPENAI_BASE_URL=http://127.0.0.1:8800/v1
```

Это не языковая модель — она детерминированно отдаёт ответ по токенам. Реальными
остаются HTTP, SSE, замеры TTFT/латентности и учёт токенов. Тот же
`OPENAI_BASE_URL` подходит для vLLM, Ollama или корпоративного шлюза.

## Что записывается для каждого запроса

| Сущность | Поля |
|----------|------|
| `Thread` | источник, модель, system prompt, температура, суммарные токены и стоимость |
| `Run` | статус, TTFT, полная латентность, input/output токены, стоимость, ошибка |
| `Span` | шаг рана (retrieval, вызов провайдера, роутинг агента) с длительностью |

Стоимость считается по таблице цен в `backend/app/services/providers.py`;
токены берутся из ответа провайдера, а не оцениваются, если провайдер их
возвращает.

## API

```
GET    /v1/providers               статус ключей
GET    /v1/models                  каталог
POST   /v1/models/sync             синхронизация с провайдерами
POST   /v1/models/{id}/check       реальный ping с замером задержки
POST   /v1/threads                 создать тред
POST   /v1/threads/{id}/runs       выполнить ран (SSE)
GET    /v1/runs/{id}               трейс со спанами
GET    /v1/metrics?hours=24        агрегаты
GET    /v1/activity                таймлайн для визуализации нитей
```

## Telegram: обычный бот + Business Bot

Используется официальный Bot API (`python-telegram-bot` 21.x):

| Режим | Как работает |
|-------|--------------|
| **Обычный бот** | Клиент пишет боту в личку, ИИ отвечает от имени бота |
| **Business Bot** | Premium Business аккаунт → Settings → Telegram Business → Chatbots → добавить бота. Клиенты пишут владельцу, ИИ отвечает от его имени через `business_connection_id` |

```env
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_ADMIN_ID=ваш_telegram_user_id
```

Каждый диалог Telegram получает собственный тред в платформе, а каждый ответ
агента — ран со спанами retrieval и роутинга.

## Escrow — только черновик и уведомление админу

Автоматическое создание сделок отключено. Когда клиент выбирает гаранта, ИИ
извлекает сумму и описание, создаёт черновик и отправляет админу уведомление с
деталями; сделку админ создаёт вручную.

## Локальная инфраструктура

| Компонент | Решение |
|-----------|---------|
| БД | SQLite (`data/ai_agent.db`) |
| RAG | Локальный TF-IDF индекс (`data/rag_index.json`) |
| Фоновые задачи | In-process scheduler (follow-up, мониторинг платежей) |
| Redis / Celery | Опционально, для production |
